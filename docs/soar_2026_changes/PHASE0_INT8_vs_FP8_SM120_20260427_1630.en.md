# Phase 0 result: SM120 INT8 IMMA vs FP8 QMMA microbenchmark (2026-04-27 16:30)

**Outcome**: Decisive. **INT8 IMMA on SM120 is throttled to BF16 tier (~136 TF), NOT competitive with FP8 QMMA (~280 TF).**

This eliminates **Option B (QServe W4-INT8)** from the W4A8 candidate list. See "Decision" section below.

Companion ZH: `PHASE0_INT8_vs_FP8_SM120_20260427_1630.zh.md`.

---

## Test environment

- GPU: NVIDIA RTX 6000D (`SM120`, capability `(12, 0)`) — competition fcloud instance
- Software: `torch 2.9.1+cu128`, CUDA 12.8
- Script: `/root/bench_int8_vs_fp8_sm120.py` (PyTorch wrappers — no cutlass build)
  - BF16 path: `torch.matmul(bf16, bf16)` → BF16 tensor cores
  - FP8 path: `torch._scaled_mm(fp8_e4m3, fp8_e4m3, scale_a=1, scale_b=1, out=bf16)` → FP8 QMMA
  - INT8 path: `torch._int_mm(int8, int8)` → INT8 IMMA
- Bench: 10 warmup + 50 timed iterations per shape, GPU-synced.

## Summary table

| dtype | Listed in `SM120_RTX_PRO_HARDWARE.md` | Measured at large M (16384×14336×4096) | % of FP8 peak |
|---|---|---|---|
| BF16 | 148 TF | **142.2 TF** (96% of listed) | 51% |
| **FP8** | **296 TF** | **281.0 TF** (95% of listed) | 100% |
| **INT8** | **NOT listed** | **136.6 TF** | **49%** |

Key finding: INT8 IMMA throughput on SM120 is **~half of FP8 QMMA** and **slightly below BF16** at all tested shapes. INT8 has no compute advantage on this hardware.

## Decision (per Phase 0 decision rule)

From `RESEARCH_w4a8_kernel_landscape_20260427_1530.en.md`:

> | Result | Action |
> |---|---|
> | INT8 ≥ ~250 TF (≈ FP8 tier) | Green-light QServe W4-INT8 integration |
> | INT8 ≈ ~148 TF (BF16 tier) | INT8 has no compute win on SM120; abandon W4-INT8 |
> | FP8 < ~250 TF | Spec contradiction; investigate |

Measured INT8 = ~136 TF → **abandon W4-INT8 path.**

Measured FP8 = ~280 TF → **FP8 path is real**, but recall: dense W4-FP8 kernel does NOT exist for SM120 anywhere we found. Building one is a multi-week kernel project.

## Implications for the W4A8 plan

| Path | Status after Phase 0 |
|---|---|
| Option A: dense W4-FP8 (write/port new kernel) | **Compute target real (FP8 = 281 TF)** but kernel doesn't exist; multi-week effort. **Defer** unless we have spare bandwidth. |
| Option B: QServe W4-INT8 (kernel ready) | **Killed.** INT8 runs at BF16 rate → no compute win over current Marlin W4A16. Only activation-BW win remains, which at decode bs=1 is negligible. |
| Option C: custom CUTLASS mixed-input | unchanged — last resort |

**Recommended pivot**: stop investing in W4A8 for now. Redirect optimization effort to:

1. **NVFP4 KV cache** (matches the latest weekly champion combo: W4A16 GPTQ + NVFP4/FP8 KV). Already partially scoped in `ANALYSIS_nvfp4_offline_quant_20260427_0857.{en,zh}.md`. SM120 supports FP4 tensor cores at 593 TF; KV cache memory traffic at long context is a primary bottleneck.
2. Other items in `OPTIMIZATION_CATALOG_GPTQ_FP8_DENSE.md` whose cost/benefit beats W4-FP8 kernel work.

W4-FP8 dense remains technically feasible (FP8 throughput on SM120 is real) but is a research project. Park it as a later "Option A" that requires explicit re-approval.

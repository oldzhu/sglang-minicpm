# Phase 0 结果：SM120 INT8 IMMA vs FP8 QMMA 微基准（2026-04-27 16:30）

**结论**：决定性。**SM120 上 INT8 IMMA 被压到 BF16 档位（约 136 TF），不与 FP8 QMMA（约 280 TF）竞争。**

这从 W4A8 候选清单中**淘汰选项 B（QServe W4-INT8）**。详见下文"决策"节。

配套 EN：`PHASE0_INT8_vs_FP8_SM120_20260427_1630.en.md`。

## 测试环境

- GPU：NVIDIA RTX 6000D（`SM120`，能力 `(12, 0)`）— 比赛 fcloud 实例
- 软件：`torch 2.9.1+cu128`，CUDA 12.8
- 脚本：`/root/bench_int8_vs_fp8_sm120.py`（PyTorch 封装 — 无需 cutlass 构建）
  - BF16：`torch.matmul(bf16, bf16)` → BF16 张量核心
  - FP8：`torch._scaled_mm(fp8_e4m3, fp8_e4m3, scale_a=1, scale_b=1, out=bf16)` → FP8 QMMA
  - INT8：`torch._int_mm(int8, int8)` → INT8 IMMA
- 计时：每个形状 10 次预热 + 50 次正式迭代，GPU 同步。

## 汇总表

| dtype | `SM120_RTX_PRO_HARDWARE.md` 列出值 | 大 M 实测（16384×14336×4096） | 占 FP8 峰值比例 |
|---|---|---|---|
| BF16 | 148 TF | **142.2 TF**（列出值的 96%） | 51% |
| **FP8** | **296 TF** | **281.0 TF**（列出值的 95%） | 100% |
| **INT8** | **未列出** | **136.6 TF** | **49%** |

关键发现：SM120 INT8 IMMA 吞吐**约为 FP8 QMMA 的一半**，且**在所有测试形状上略低于 BF16**。INT8 在该硬件上无算力优势。

## 决策（依 Phase 0 决策规则）

引自 `RESEARCH_w4a8_kernel_landscape_20260427_1530.zh.md`：

> | 结果 | 行动 |
> |---|---|
> | INT8 ≥ ~250 TF（≈ FP8 档位） | 放行 QServe W4-INT8 集成 |
> | INT8 ≈ ~148 TF（BF16 档位） | INT8 在 SM120 上无算力收益；放弃 W4-INT8 |
> | FP8 < ~250 TF | 与官方规格冲突；先排查 |

实测 INT8 = ~136 TF → **放弃 W4-INT8 路径。**

实测 FP8 = ~280 TF → **FP8 路径是真实的**，但回顾：稠密 W4-FP8 kernel 在 SM120 上**任何已知地方都不存在**。从零写或移植是数周工作量。

## 对 W4A8 计划的影响

| 路径 | Phase 0 后状态 |
|---|---|
| 选项 A：稠密 W4-FP8（写/移植新 kernel） | **算力目标真实（FP8 = 281 TF）**但 kernel 不存在；数周工作量。除非有富余带宽，**搁置。** |
| 选项 B：QServe W4-INT8（kernel 现成） | **淘汰。** INT8 跑在 BF16 速率 → 相比当前 Marlin W4A16 无算力收益。只剩激活带宽收益，decode bs=1 时可忽略。 |
| 选项 C：自定义 CUTLASS 混合输入 | 不变 — 最后保留 |

**建议转向**：暂停在 W4A8 上的投入。把优化精力转到：

1. **NVFP4 KV 缓存**（匹配最新一周冠军组合：W4A16 GPTQ + NVFP4/FP8 KV）。`ANALYSIS_nvfp4_offline_quant_20260427_0857.{en,zh}.md` 已部分立项。
   **重要澄清**：NVFP4 KV 缓存是**仅存储压缩** — K/V 在 HBM 中以 FP4 存储（相对 FP8 KV：**KV 内存 −50% + KV 带宽 −50%**；相对 BF16 KV 为 4×），但注意力计算时 K/V 会被反量化回 **BF16** 再进矩乘，还是在 BF16 张量核心 148 TF 上跑。**593 TF FP4 张量核心峰值在这里用不上**（FP4 张量核心需 GEMM 两侧输入都是 FP4）。收益在**长上下文的内存系统**上，不是算力。
2. `OPTIMIZATION_CATALOG_GPTQ_FP8_DENSE.md` 中性价比胜过 W4-FP8 kernel 工作的其他条目。

W4-FP8 稠密在技术上仍可行（SM120 FP8 吞吐为真），但是研究项目。作为后续"选项 A"留档，需显式重新审批。

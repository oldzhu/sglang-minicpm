## 根因调查：为什么新瓦片未被选中

### 1. 评分公式

`gptq_marlin.cu` 中 SM120 评分器（`score_sm120_candidate()`）计算：

```
score = fill_ratio  × 1000.0     （主导项：SM 槽位填充比例）
      + wave_ratio  × 100.0      （总工作波次，上限 4）
      + m_coverage  × 10.0       （M 瓦片实际利用比例）
      + smem_fit    × 1.0        （共享内存越小越好）
      + occupancy   × 0.5        （每 SM 并发块数）
      + total_tiles × 0.01       （决胜项）
```

**`fill_ratio × 1000` 完全主导** — 衡量 GPU 总 SM 槽位被瓦片填充的比例。其他项之和最高约 410 分。评分器极端偏好**产生更多瓦片**以填满所有 SM。

### 2. MiniCPM-SALA 权重形状

模型每次前向传播有 153 次 GEMM 调用：

| 层 | N | K | 数量 | 量化 |
|----|---|---|------|------|
| gate_up_proj（MLP） | 28672 | 4096 | 32 | W4 g128 |
| down_proj（MLP） | 4096 | 14336 | 32 | W4 g128 |
| 标准 qkv_proj | 6144 | 4096 | 8 | W8 g128 |
| 标准 o_proj | 4096 | 4096 | 8 | W4 g128 |
| lightning qkv_proj | 3072 | 4096 | 24 | W4 g128 |
| lightning o_proj | 4096 | 1024 | 24 | W4 g128 |
| z_proj | 1024 | 4096 | 24 | W4 g128 |
| lm_head | 150528 | 4096 | 1 | FP16（非 Marlin） |

模型架构：8 个标准注意力层 + 24 个 lightning（SimpleGLA）层，均含 MLP。

### 3. 瓦片数量分析：宽瓦片为何失败

RTX PRO 6000（SM120/Blackwell GB202）有 **96 个 SM**。关键问题是每种配置对给定 GEMM 形状产生多少瓦片。

对于日志中的形状 **M=20, N=4608, K=4096**（标准 qkv_proj，`thread_m_blocks=2` → tile_m=32）：

| 配置 | thread_n | n_tiles (N/thread_n) | m_tiles | total_tiles | fill_ratio (÷96) | 得分（主导项） |
|------|----------|----------------------|---------|-------------|-------------------|----------------|
| **{16,8,256}** 新 | 256 | 18 | 1 | **18** | 0.19 | **~188** |
| **{16,4,256}** 新 | 256 | 18 | 1 | **18** | 0.19 | **~188** |
| **{8,8,256}** 新 | 128 | 36 | 1 | **36** | 0.38 | **~375** |
| {8,4,128} 已有 | 128 | 36 | 1 | **36** | 0.38 | **~375** |
| **{4,8,128}** 已有 | 64 | 72 | 1 | **72** | 0.75 | **~750** ← 胜出 |

已有的 `{4,8,128}` 在得分上**高出 2-4 倍**，因为产生 72 个瓦片对比 18-36 个。`thread_n=256` 仅产生 18 个瓦片时，96 个 SM 中有 78 个空闲。

### 4. 即使最大的 N（28672）也无法拯救宽瓦片

对于 gate_up_proj（N=28672，宽瓦片最有利的情况）：

| 配置 | thread_n | n_tiles | fill_ratio (÷96) | wave_ratio × 100 |
|------|----------|---------|-------------------|-------------------|
| {16,8,256} | 256 | 112 | 1.0（满载！） | 112/96 = 1.17 → **117** |
| {4,8,128} | 64 | 448 | 1.0（满载！） | 448/96 = 4.67 → 上限 **400** |

fill_ratio 并列 1.0 时，`wave_ratio × 100` 决胜。窄瓦片获得 400 分对比 117 分 — 283 分的不可逾越差距。

### 5. 宽瓦片获胜的最小 N 值

`thread_n=256` 要有竞争力，需要 `total_tiles ≥ SM数`（96）：
- `n_tiles = N / 256`，`m_tiles = ceil(M / tile_m)`
- 解码（M=1，m_tiles=1）：需要 N ≥ 96 × 256 = **24,576**
- 小 prefill（M=20，m_tiles=1）：需要 N ≥ **24,576**

MiniCPM-SALA 最大 N 维度为 28,672（gate_up_proj）— 仅略高于阈值。但即便如此，窄瓦片仍通过 wave_ratio 胜出。**MiniCPM-SALA 中没有任何层能从 `thread_n=256` 瓦片受益。**

### 6. 模板参数物理含义

```
thread_m_blocks: M 瓦片数，每瓦片 16 行 → 覆盖 = thread_m_blocks × 16
thread_n_blocks: N 瓦片数，每瓦片 16 列 → 覆盖 = thread_n_blocks × 16
thread_k_blocks: K 迭代步长，每步 16 元素 → 每步 K = thread_k_blocks × 16
num_threads: 每线程块线程数（128 = 4 warp，256 = 8 warp）
```

使用的 MMA 指令是 **`mma.sync.aligned.m16n8k16`**（SM80 时代），**不是** SM120 原生 warp 级 MMA。

### 7. SM120 瓦片改动从根本上无法帮助的原因

三个独立原因：

**A. 指令集不匹配**：Marlin 使用 SM80 的 `mma.sync.aligned.m16n8k16`。SM120 Blackwell 有更高吞吐量的原生 warp 级 MMA，但 Marlin 未使用。瓦片形状改动无法触及 SM120 硬件能力。

**B. 占用率物理限制**：宽瓦片产生更少的线程块。96 个 SM 配合 MiniCPM 的 N ≤ 28,672，宽瓦片总是让 SM 空闲。评分器正确识别了这一点。

**C. 访存受限场景**：在小 M（解码，M=1-8）时，GEMM 受内存带宽限制。瓶颈是从 GDDR7（1398 GB/s）加载 W4 权重，而非计算。更多瓦片将内存访问分散到更多 SM，效果更好。

## 在 SM120 上真正有帮助的方案

| 方案 | 影响 | 工作量 | 风险 | 说明 |
|------|------|--------|------|------|
| **SM120 原生 warp 级 MMA** | 高（可能 2×） | 非常高 | 高 | 重写 Marlin 核心使用 SM120 MMA 替代 SM80 mma.sync |
| **TMA（张量内存加速器）** | 中 | 高 | 中 | 异步内存加载，比当前共享内存暂存更好的流水线 |
| **QMMA (mxfp8)** | 高（对比 FP16 有 2×） | 中 | 精度风险 | SM120 有 296 TFLOPS FP8 对比 148 TFLOPS BF16，需要 FP8 GEMM 路径 |
| **CUTLASS 3.x SM120 核心** | 高 | 非常高 | 中 | 用 CUTLASS sm120 GEMM 完全替换 Marlin（NVIDIA 优化路径） |
| **TRT-LLM SM120 参考** | 可能高 | 高 | 中 | 竞赛提示："TRTLLM will give user some reference usage" 用于 SM120 |
| 评分权重调优 | 可忽略 | 低 | 低 | 无帮助 — 评分器已在做正确决策 |
| 更多瓦片实例化 | 无 | 低 | 无 | 同样的问题 — 更多可选瓦片在基本面错误时无济于事 |

### 关键硬件规格（来自竞赛 PDF）

| 特性 | 值 |
|------|-----|
| 架构 | SM120（Blackwell） |
| BF16/FP16 张量核心 | 148 TFLOPS |
| FP8 张量核心 | 296 TFLOPS |
| FP4 张量核心 | 593 TFLOPS |
| GPU 显存 | 84 GB GDDR7 |
| 显存带宽 | 1398 GB/s |
| L2 缓存 | 112 MB |
| MMA | Warp 级（非 warpgroup 级） |
| TMA | 支持 |
| QMMA | 支持 (mxfp8) |

与 Hopper（SM90）的关键区别：MMA 是 **warp 级**而非 warpgroup 级。竞赛主办方表示优化策略"基本类似 Hopper"。

## 结论

1. **CHANGE_0125 功能上中性** — 新瓦片编译成功但评分函数正确地从未为 MiniCPM-SALA 的权重形状选中它们。

2. **评分函数没有问题** — 它正确识别了窄瓦片（thread_n=64）对该模型 N 维度（1024-28672）最大化 SM 利用率。

3. **调优评分函数是死路** — 窄瓦片的占用率优势是物理现实，不是评分偏差。

4. **SM120 硬件优势（原生 MMA、TMA、QMMA）通过瓦片改动无法触及** — Marlin 无论瓦片配置如何都使用 SM80 时代的指令。

5. **真正受益于 SM120**：需要内核级改动使用 SM120 原生 MMA 指令，或切换到 CUTLASS/TRT-LLM SM120 内核。这远超瓦片调优的范畴。

6. **建议**：CHANGE_0125 可保留（无害）或回退（节省增量编译约 1 分钟）。Marlin 瓦片优化路径对 MiniCPM-SALA 已穷尽。未来 GEMM 优化应聚焦 SM120 原生内核集成。

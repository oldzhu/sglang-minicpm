# CHANGE_0140 — Disable `enable_thinking` for mcq prompts via chat-template patch (Phase 14.1)

**Status**: Implemented locally; awaiting fcloud validation
**Iteration**: Round 14.1 (per [PROPOSAL_round14_local_accuracy_improvement.en.md](PROPOSAL_round14_local_accuracy_improvement.en.md))
**Baseline**: v20 (commit `205d8cb91`, `SOAR_BACKEND_VARIANT=flashinfer`)
**Scope**: mcq task only — qa/niah/cwe/fwe unaffected
**Files touched**: `benchmark/soar/demo_sala/preprocess_model.py`, `benchmark/soar/demo_sala/prepare_env.sh`

---

## 1. Background and motivation

The eval harness ([eval_model_001.py:352](../../benchmark/soar/demo_sala/eval_model_001.py#L352)) sends `chat_template_kwargs={"enable_thinking": True}` for every task. For mcq this triggers a `<think>...</think>` reasoning block whose closing tag the model frequently fails to emit within the per-request token budget. The harness's `extract_final_answer` function ([line 176-178](../../benchmark/soar/demo_sala/eval_model_001.py#L176-L178)) splits on `</think>`; when the tag is missing, the regex `(?i)ANSWER\s*:\s*([A-D])` runs over the entire (unclosed, often truncated) thinking blob and usually fails to find a clean letter.

Result: bimodal mcq accuracy — across identical-binary runs, mcq scored 40–63% in the 13f-4 quartet (A1=40%, A2=53%, A3=60%, A4=63%) purely on whether `</think>` happened to be sampled. Lucky runs from prior batches reached 96.67% (Test 29 reference).

Lifting mcq from the ~55% mean to its already-observed lucky plateau ~90–96% raises overall accuracy by **+7 pt** (mcq is one of 5 equally weighted tasks). The fix has zero speed cost on the official S1/S8/Smax benchmarks because those datasets contain no mcq prompts.

## 2. Rule compliance

- **Eval-script integrity**: `eval_model_001.py` is NOT modified. The fix is server/model-side only.
- **Submission tarball**: the patch lives in `preprocess_model.py`, which IS in the tarball and IS executed by the official runner at submission-prep time. Therefore the patched `chat_template` reaches official inference identically to local inference.
- **No forbidden behavior**: no prefix-cache trick, no harness override, no concurrency violation.
- **Reversible**: `SOAR_DISABLE_MCQ_THINKING=0` env var disables the patch for A/B testing.

## 3. Detection signal

Every mcq prompt in `perf_public_set.jsonl` contains the literal substring:

```
LETTER is one of ABCD
```

…inside the instruction wrapper:

> "The last line of your response should be of the following format: 'ANSWER: \$LETTER' (without quotes) where LETTER is one of ABCD."

Verified all 30 mcq prompts in the public set carry this exact phrase. Non-mcq prompts (qa/niah/cwe/fwe) do not contain it. False-positive rate on the public set: 0%.

The instruction is generated by the harness, not the dataset, so the **same string is expected in the private set**. (The official set contains `mcq` as a task type per the rules; the harness prompt template is unchanged across submissions per the organizers' announcement.)

## 4. Implementation

### 4.1 Jinja preamble

A small Jinja preamble is prepended to the model's existing `chat_template` in `tokenizer_config.json`. The preamble:

1. Initializes a namespace variable `_soar_ns.et` from the input `enable_thinking` (default `true` if undefined).
2. Iterates over `messages`; if any message's content contains `LETTER is one of ABCD`, sets `_soar_ns.et = false`.
3. Top-level rebinds `enable_thinking = _soar_ns.et` so the rest of the template observes the override.

The Jinja2 `namespace()` pattern is required because `{% set %}` inside `{% if %}` / `{% for %}` blocks is local to those blocks and does NOT escape scope. Mutating a namespace attribute IS visible across scopes; the final top-level `{% set enable_thinking = _soar_ns.et %}` then rebinds globally.

```jinja
{# SOAR_MCQ_THINKING_DISABLE_v1 #}
{%- set _soar_ns = namespace(et=(enable_thinking if enable_thinking is defined else true)) -%}
{%- if messages is defined and messages -%}
{%- for _m in messages -%}
{%- set _c = _m['content'] if (_m['content'] is defined and _m['content'] is string) else '' -%}
{%- if 'LETTER is one of ABCD' in _c -%}
{%- set _soar_ns.et = false -%}
{%- endif -%}
{%- endfor -%}
{%- endif -%}
{%- set enable_thinking = _soar_ns.et -%}
```

The marker comment `{# SOAR_MCQ_THINKING_DISABLE_v1 #}` is used for idempotency: re-running `preprocess_model.py` on an already-patched directory is a no-op.

### 4.2 `preprocess_model.py` change

A new function `_patch_chat_template_for_mcq(dst)` is added near `main()`. It:

- short-circuits if `SOAR_DISABLE_MCQ_THINKING` is falsy;
- short-circuits if `tokenizer_config.json` is missing;
- short-circuits if the marker comment is already present;
- otherwise prepends the preamble and writes back atomically (`tmp_path.replace(tok_path)`).

It is invoked at the end of both the `copy` and `gptq` mode branches in `main()`, so all submission flows produce a patched template.

### 4.3 `prepare_env.sh` change

Added near the v20 backend block:

```bash
export SOAR_DISABLE_MCQ_THINKING="${SOAR_DISABLE_MCQ_THINKING:-1}"
```

Default ON. To disable for A/B: `export SOAR_DISABLE_MCQ_THINKING=0` before invoking `preprocess_model.py`.

## 7. Rollback

```bash
# Disable at runtime (no rebuild needed)
export SOAR_DISABLE_MCQ_THINKING=0

# Or revert the commit
git revert <change-0140-commit>
```

Even with the patch present, an unpatched model directory (no marker comment) will be re-patched on next `preprocess_model.py` run. To start clean: copy the original `tokenizer_config.json` from the input directory.

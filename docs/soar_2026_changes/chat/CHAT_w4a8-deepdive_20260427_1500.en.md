## Round 6 — FP4 misstatement correction + chat-tracking rule (this round)

### User asks
> "I would like to add one more document rule about chat into copilot instructions and our project persist memory: document every round of our interaction into a document name suffix is datetime in a new sub folder.
> Regarding W4A16 GPTQ + NVFP4/FP8 KV: SM120 has 593 TF FP4 + KV memory traffic is the long-context bottleneck — better cost/benefit than building a new W4-FP8 GEMM, why? The activation is still BF16 so compute and part of memory are still BF16 typed, am I right? I don't think the combination can use 593 TF FP4, am I right?"

### Agent answer / action
- **User is correct on FP4.** NVFP4 KV cache is **storage-only compression**:
  - K/V stored in HBM as FP4 → −50% KV memory + −50% KV bandwidth vs FP8 KV (4× vs BF16 KV)
  - During attention, K/V are dequantized to BF16 → matmul still on BF16 tensor cores (148 TF), NOT FP4 (593 TF)
  - Activation precision unchanged at BF16
  - **The win is memory-system, not compute.** 593 TF FP4 only matters when both GEMM inputs are FP4.

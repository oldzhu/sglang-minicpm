## 第 1 轮 — 初次速度基准 + 命名错误发现

### 用户提问

> 接着："w4a8 比 v18 基线还差很奇怪 ... v18 基线其实不是 w4a8（存储和计算都是 fp8），它是 w4a16 ... 真正的 w4a8 应该比 v18 基线更好，这里出了什么问题？"

### Agent 回答 / 操作

### 结果

- 更新 `TEST_RESULTS_TRACKING.md` 中 W4A8-#1 行加 `(MISLABEL: actually W8A8 FP8)` 标注。

## 第 3 轮 — 现有 kernel 清单 + 4 个开放问题

### 用户提问
> "1. 内存与算力都更好就批准。2. 哪个选项更好？利弊？还有别的选项吗？sgl-kernel 没有现成 w4a8(fp8)？3. 可以在 fcloud 测，请记录命令脚本和结果 ... 4. 上周冠军没人做真实 w4a8(fp8)，所以路径可行性未知。vllm machete 有 w4a8(fp8) kernel 吗？"

### Agent 回答 / 操作
代码搜索核实：
- **`qserve_w4a8_per_group_gemm` 与 `_per_chn_gemm`** 已在 sgl-kernel 中（`csrc/gemm/qserve_w4a8_per_*.cu`）— INT4 权重 + INT8 激活，稠密 GEMM，SM80+ → SM120 应能跑。
- **`cutlass_w4a8_moe_mm`** 在 sgl-kernel 中（`csrc/moe/cutlass_moe/w4a8/`）— INT4 + FP8 e4m3，但**仅 SM90 MoE**，非稠密。
- **vllm Machete**（`csrc/quantization/machete/`）— README 明确 `compute_type = a.dtype`（BF16/FP16）。Machete 是 **W4A16，不是 W4A8**。
- **结论**：SM120 上稠密 W4-FP8 没有现成 kernel；稠密 W4-INT8 有现成（QServe）。优先级翻转：FP8 路径成多周 kernel 项目，INT8 路径成低工作量集成 *如果* Phase 0 微基准通过。

### 结果
- 口头答 4 个开放问题：批准选项 A 是/否、kernel 来源约束、是否跑 Phase 0、工作量预算。
- 本轮无新提交（仅分析）。

## 第 6 轮 — FP4 表述纠正 + 会话追踪规则（本轮）

### 用户提问
> "想加一条文档规则关于 chat：把每轮交互记录到日期时间后缀的文档（建一个新子文件夹）。
> 关于 W4A16 GPTQ + NVFP4/FP8 KV：你说 SM120 有 593 TF FP4 + KV 内存流量是长上下文瓶颈，比建新 W4-FP8 GEMM 性价比高，为什么？激活仍是 BF16 所以算力和部分内存还是 BF16 类型，对吧？这种组合用不到 593 TF FP4，对吧？"

### Agent 回答 / 操作
- **用户对 FP4 判断正确。** NVFP4 KV 缓存是**仅存储压缩**：
  - K/V 在 HBM 中以 FP4 存储 → KV 内存 −50% + KV 带宽 −50%（vs FP8 KV；vs BF16 KV 为 4×）
  - 注意力计算时 K/V 反量化回 BF16 → 矩阵乘仍在 BF16 张量核心（148 TF），**不在** FP4（593 TF）
  - 激活精度仍是 BF16
  - **收益是内存系统，非算力。** 593 TF FP4 只在 GEMM 两侧输入都是 FP4 时才有用。
